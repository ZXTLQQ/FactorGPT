# 方法论扩展与工程优化说明

本文记录本轮两方面的改动：**四项工程优化**（安全 / 性能 / 静态检查 / 取数），
以及**方法论与分析侧的扩展**（方法库、风险+预测双引擎、多因子体系、深度分析报告）。

---

## 一、四项工程优化

### 1. 安全：消除最后一处裸 `eval`

`src/engine/unstructured_miner.py` 此前直接用 `eval(factor_expr, {"df": df, "np": np})`
求值 LLM/用户给出的因子表达式，是全仓唯一没有隔离的任意代码执行点
（`factor_builder` 与 `_sandbox_runner` 已有白名单 + 子进程隔离）。

新增 `src/engine/safe_expr.py`：以 AST 白名单替代裸 eval——只放行算术 / 比较 /
下标 / 方法调用类节点，拒绝 import、赋值、推导式，并**拒绝任何以 `_` 开头的属性**
（`__class__` / `__globals__` / `__subclasses__` 逃逸链）。同时校验结果长度必须为
标量或与数据等长，避免异形对象静默污染下游回测。

已验证可拦截：`__import__('os')...`、`df.__class__`、`open('x')`。

### 2. 性能：回测主循环 O(T²·N) → O(T·N)

`src/engine/backtest.py` 主循环原先在每个交易日执行一次全表布尔扫描
`panel[panel["date"] == t]`。按默认区间（约 1200 个交易日 × 800 只）估算即 10⁹ 量级比较。

改为进入循环前一次性 `groupby("date")` 预切分，循环内 O(1) 取用；组合收益与
涨跌停筛选改为向量化。语义保持不变（NaN 收益仍按 0 贡献计）。

### 3. 静态检查：ruff 接入 CI

- 新增 `ruff.toml`，采用**渐进式放开**：先启用高价值低噪声规则
  （F / E4/E7/E9 / W / I / B / S / C4 / UP / SIM / RUF），把存量但改动面广的规则
  列入豁免并写进文件末尾的 ROADMAP（批次 2/3/4）。
- 中文项目固有的 `RUF001/002/003`（全角标点）已豁免；
  `RUF100`（unused-noqa）刻意关闭——它会按「当前启用规则」判定 noqa 多余而误删
  尚在豁免队列中的标记。
- CI 增加 Lint 步骤（`pip install "ruff==0.16.*"` + `ruff check src scripts tests`），
  锁大版本以避免规则漂移导致 CI 意外转红。

本轮实际修出的问题：5 个文件缺 `typing` 导入（43 处 `F821`，在 `from __future__
import annotations` 下不报错但 `get_type_hints` 会炸）、`market_hub.py` 漏导入
`NS_INTRADAY`（`_render_db_status()` 必然 NameError）、`mining/ops.py:693` 调用
不存在的 `_elem`（已补一元逐元素函数）、`scripts/deploy_all.py` 的 `space_name`
未转义 f-string 与 3 处裸 `except:`。

### 4. 取数：并发 + 缓存命中 + 补齐限流

发现 `config.yaml` 的 `data.request_interval` **此前没有任何代码读取**——防封 IP 的保护
实际未生效。本轮补齐：

- 新增 `_RateLimiter`：单调时钟 + 锁发放请求许可，sleep 在锁外执行，并发线程只排队不互锁。
- `_fetch_batch` 支持线程池并发（`data.max_concurrency`，默认 1 保持历史行为）。
  每个请求都先取许可，并发不会绕过限流。
- 新增 `data.cache_read_first` + `data.cache_ttl_hours`：此前缓存只在「实时源全失败」
  时才读，正常路径每次都重打网络；开启后区间不变的重复回测可秒级复跑。默认 `false`，
  保持「每次取实时数」语义。

新增配置项（均已在 `config.yaml` 注释说明）：

| 配置项 | 默认 | 含义 |
|---|---|---|
| `data.request_interval` | 0.5 | 全局最小请求间隔（秒），现已真正生效 |
| `data.max_concurrency` | 1 | 批量取数并发度，2~4 可显著缩短耗时 |
| `data.cache_read_first` | false | 正常路径也先查缓存，命中即返回 |
| `data.cache_ttl_hours` | 0 | >0 时缓存超时即视为未命中 |

## 二、方法论扩展

### 1. `src/engine/method_hub.py` —— 方法库与智能选择

| 视角 | 函数 | 说明 |
|---|---|---|
| 贝叶斯 | `bayesian_ic_weights` | IC 的正态-正态共轭后验收缩，样本少 / 波动大的因子自动降权 |
| 贝叶斯 | `bayesian_tpe_search` | TPE 贝叶斯优化（好/坏分布 + 密度比采样），用于权重与超参搜索 |
| 贝叶斯 | `bayesian_model_average` | 多方案按评分 softmax 后验融合 |
| 博弈论 | `shapley_attribution` | 合作博弈 Shapley 值，衡量因子**在组合中**的真实贡献（k≤8 精确枚举，k>8 置换蒙特卡洛） |
| 博弈论 | `nash_bargaining_weights` | 多目标（IC/换手/稳健性）纳什议价解，不被单一目标绑架 |
| 主成分 | `pca_decomposition` | SVD 实现的 PCA：载荷、解释方差、统计因子 |
| 主成分 | `effective_rank` | 有效秩（参与率熵），量化因子体系分散程度 |
| 智能选择 | `select_method` / `profile_from_ic` | 按样本量、因子数、信噪比、共线性给出推荐方法与理由 |

`select_method` 的规则是可解释的：样本极少 → 线性；信噪比低 → 贝叶斯收缩；
共线性高 → 先 PCA 去冗余；样本充足且因子适中 → 树模型；存在 regime → contextual。

### 2. `src/engine/twin_model.py` —— 风险模型 + 预测模型

- **鲁棒预测模型**：`fit_robust_predictor` 用 IRLS 自实现 OLS / Huber / LAD(L1)，
  零新增依赖；`robustness_curve` 做加噪与剔除极端样本的压力测试，
  `recommend_predictor` 按「扰动下衰减最小」推荐。默认推荐 Huber。
- **可解释风险模型**：`InterpretableRiskModel` 做结构化风险分解——
  因子协方差（Ledoit-Wolf 收缩）+ 特异方差，输出边际风险贡献 MCTR、
  成分风险贡献 CCTR、风险集中度 HHI、有效下注数，以及各风格因子的风险占比。
  `explain()` 直接产出可读归因文本。
- **衔接**：`combine_signal_and_risk` 把预测信号按单标的上限与单因子暴露上限约束成权重。

风险分解不显式构造 N×N 协方差，而是用 `(Σw)_i = B_i'F(B'w) + Δ_i w_i`，复杂度 O(N·K)。

### 3. `src/engine/factor_synthesis.py` —— 多因子体系

逐层可对照、可回退：

1. **线性 baseline**：`equal` / `ic` / `icir` / **`max_ic`**（最大化组合 ICIR 的解析解
   w ∝ Σ_IC⁻¹ μ_IC，协方差用 Ledoit-Wolf 收缩）/ `regression` / `bayesian`。
   `max_ic` 是整个体系的标尺。
2. **显式非线性**：交互项、二次项、符号幂、分位项，前向贪心 + 验证集早停挑选，
   每一项都可写出公式（区别于黑箱）。
3. **树模型**：GBDT 合成 + 特征重要性；`scikit-learn` 不可用时明确降级，不静默失败。
4. **Contextual modeling**：按波动 regime / 涨跌趋势（或自定义 context 列）分别估计
   max IC 权重，解决「同一套权重在不同状态下互相抵消」。

`build_factor_system` 串联各层并输出增益表与推荐：**只有某层的样本外 IC 相对
baseline 提升超过阈值（默认 10%）才采用，否则退回 baseline**（可解释性优先）。

实测示例中，树模型样本内 IC 0.334 但样本外仅 0.114（典型过拟合），
体系据此正确退回 `linear:max_ic`（样本外 IC 0.190 / ICIR 1.83）。

### 4. `src/reporting/factor_report.py` —— 回测后深度分析

- **统计体检**：`statistical_diagnostics` 输出 Newey-West 稳健 t、bootstrap 置信区间、
  Jarque-Bera 正态性、Ljung-Box 自相关、IC 衰减、分位单调性（Spearman + 首尾价差）、
  Sharpe / Sortino / Calmar / 最大回撤 / 月度胜率、换手与成本假设。
- **12 张图表**：IC 序列、IC 分布、滚动 IC/ICIR、IC 衰减、分位收益、分位累计、
  净值与回撤、月度热力图、收益分布、换手序列、因子相关性、指标汇总。
- **大模型解读**：`llm_interpret` 把完整统计画像（图表以清单 + 关键数值表示，
  因为模型看不到图）喂给 LLM，要求「只依据给定数字、先看统计显著性再看经济显著性、
  指出最大风险点、给出可执行建议」；**LLM 不可用时降级为规则化结论，绝不静默跳过**。

### 5. 统一入口 `src/pipeline/deep_analysis.py`

```python
from pipeline.deep_analysis import deep_analysis, write_report_bundle

res = deep_analysis(kline, factor, factor_name="mom_rev", factor_expr="mom - rev",
                    extra_factors=panel[["date", "symbol", "vol", "rev"]],
                    run_system=True)
print(res["report"].to_markdown())          # 统计 + 图表清单 + 分析结论
print(res["report"].charts)                 # 图表路径
print(res["report"].interpretation["text"]) # LLM 解读（或规则化降级）
paths = write_report_bundle(res)            # 落盘 Markdown + 指标 CSV
```

一次调用完成：回测 →（可选）组合级回测 →（可选）多因子体系 → 统计体检 → 图表 → 解读 → 落盘。

### 6. 深度分析自动挂钩挖掘流水线（本轮新增）

`deep_analysis` 原先只能显式调用。现在在 `pipeline/refinery.py` 的 PART-05 合成之后、
PART-06 方法学总结之前挂了一次自动调用（`_stage07_deep_analysis`），开箱即得：

- 开关：`refinery.deep_analysis`（默认 true）、`deep_analysis_dir`（默认
  `output/factor_report`）、`deep_analysis_system`（是否额外跑体系搭建）、
  `deep_analysis_max_factors`（参与体系搭建的入选因子上限，按 |IC| 排序截断，默认 12）。
- 产物：`{名称}_report.md` + `metrics.csv` + 10~11 张图表，落 `deep_analysis_dir`；
  摘要写进 `RefineryResult.deep_analysis`，含报告路径、图表清单、解读口径
  （`llm` / `rule`）、指标数、体系推荐方案与对比层级。
- 入选因子由 `_screened_to_frame` 拼成 `(date, symbol, 因子列)` 宽表，
  既供体系搭建，也供因子相关性热力图；不足 2 个因子时自动跳过体系层。
- 方法学报告新增「十二、深度分析」章节：引用独立报告与指标 CSV 路径、图表清单、
  解读来源、**完整解读正文**（引用块）、多因子体系推荐方案与样本外 IC。
  JSON 产物同步带 `deep_analysis` 字段（去掉解读正文避免膨胀）。
- 任一环节异常只告警不中断主流程，`result.deep_analysis` 置 None。
- 深度分析置于方法学总结之前，保证第十二章能引用其产物。

### 7. 净值统计量口径修正（本轮修复）

`_drawdown_stats` 原先把任意长度的净值序列硬性按 252 天年化，40 期样本上会把
2.8 倍区间收益外推成 678 倍「年化」，Calmar 跟着失真到 815。现改为：

- `_infer_periods_per_year`：日频取 252；索引为 DatetimeIndex 且中位间隔 > 3 天时
  按实际间隔折算（周频 52 / 月频 12）。
- 样本长度 < max(20, ppy/2) 时**不做年化外推**，`annualized=False`，
  Calmar 改用「区间累计收益 / 最大回撤」，并在报告与规则化解读中标明口径。
- 报告第四章增列「区间累计收益」与统计口径说明，年化行在不足半年时显示为「—」。

## 三、验证结论

- 静态检查：`ruff check src scripts tests` 全部通过。
- 回归测试：`pytest tests/` **313 passed, 1 skipped**（新增 2 条深度分析挂钩用例）。
- 新增模块端到端验证（合成数据，含 1% 异常收益）：安全表达式拦截、TPE 收敛到
  `[0.304, -0.257]`（真值 `[0.3, -0.2]`）、Shapley 归因把主要贡献分配给 `mom`
  （数据由 mom 驱动，符合预期）、纳什权重归一、风险模型有效下注数 60（等权 60 只）、
  六类线性方案 + 非线性 / 树 / contextual 全部跑通、报告生成 11 张图表。
- 本轮修复的实现级缺陷：TPE 启动采样把维度固定绑定到分层（导致 w0 只能取负半轴）、
  风险贡献占比误除以方差（应为标准差，否则占比和不为 1）。

## 四、遗留与下一步

- `ruff.toml` 的 ROADMAP 批次 2/3/4（命名、复杂度、类型注解、docstring）尚未放开。
- 深度分析已自动挂钩精炼厂；若要在 Agent 回测节点后也产出报告，再挂一次
  `deep_analysis` 即可（精炼厂入口为 `refinery.deep_analysis`）。
- 树模型依赖 `scikit-learn`（已在 requirements 的「因子精炼厂可选依赖」段）。
- 净值统计量已按样本长度区分年化/区间口径；若接入分钟级或周月频数据，
  确认 `_infer_periods_per_year` 的折算是否符合该频次的交易日历。
