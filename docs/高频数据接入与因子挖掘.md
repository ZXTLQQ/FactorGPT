# 高频数据接入与订单簿因子挖掘

> 本文记录把两份离线数据 —— **全市场期货 L2 五档快照**（`20251208.pqt`）与
> **自身委托流水**（`20251208_orders.xlsx`） —— 接入 FactorGPT 的全过程，
> 以及由此生长出来的三件东西：**订单簿因子层**、**订单簿监督模型层**、**四类高频策略层**。
>
> 所有数字均在下列环境下实测得出：单实例 Python 3.13 / pandas 2.3.3 / numpy 2.5.1，
> 单日快照 15.8M 行 / 795 合约 / 82 品种。**样本只有一天，所有结论都必须按「单日证据」理解。**

## 1. 数据画像：先搞清楚手上到底有什么

| 项 | 值 |
| --- | --- |
| 快照文件 | `20251208.pqt`，15.8M 行 × 795 合约 × 82 品种 |
| 采样频率 | **500ms 快照**（不是逐笔！） |
| 单合约上限 | 约 6.4 万行 ≈ 8.9 小时 × 500ms（夜盘 + 日盘） |
| 每次快照 | 五档买/卖价量、`Volume`/`Turnover`/`OpenInt`（当日**累计**量）、`DayHigh/DayLow`、衍生撤单/笔数列 |
| 委托流水 | 委托时间、合约、方向、价格、数量、是否成交 |

**这条 500ms 的性质决定了整套方法学**：拿不到逐笔委托流，就无法还原严格意义的
Cont, Stoikov & Talreja (2014) OFI；能做的只有「相邻两个快照之间、按**价格**匹配的队列净变化」，
即 OFI 的**快照近似**。这一条写在因子函数 docstring 里，不允许在实现里被稀释。

## 2. 三个坑（以及它们各自对应的接头）

坑不是「注意一下」就够了 —— 每一个都真的把结果**算错过**，且都是静默的。

### 坑 1：`SortTime` 是跨自然日的连续时钟

`SortTime` 编码为 `HHMMSSmmm`，小时位覆盖 `20..39`（`39` 表示次日下午 15:00）。

正确还原方式（`src/data/hf_adapter.py::_sorttime_to_wallclock`）：

- 墙上时钟 `HH % 24`；
- 夜盘 / 集合竞价段（会话 `N`/`A`/`a`）自然日取 **`CalDate`** —— 该列**已包含午夜进位**，
  因此**绝不能再额外 +1 天**；
- 日盘段（`M`/`E`）自然日取 `Date`。

> 第一版实现就是多加了这一天的进位，结果夜盘被整体平移到 12-07，
> 与自身委托流水的秒级交集体检出为 **0**。
> 交叉表证伪：`HH>=24` 的行，`TimeStr` 的小时 `== HH%24` 命中率 100%（全市场 795 合约验证）。
> 修正后时间轴为 `12-05 21:00 → 12-06 02:30`（夜盘）、`12-08 09:00 → 15:00`（日盘）。

### 坑 2：会话空洞比正常采样间隔大四个数量级

国内期货一天四段：`N`（夜盘）、`M`（上午）、`E`（下午）、`A`/`a`（集合竞价）。
相邻快照的正常间隔是 **0.5 秒**，而**午休的空洞是 2 小时**：\(2\mathrm{h} / 0.5\mathrm{s} \approx 1.44\times 10^4\)。

后果：一切差分、滚动窗口、未来收益标签，只要在会话之首不断开，就是把午休前的状态
当作午休后的前值。因此所有相关运算都显式接收 `session_id`：

| 运算 | 做法 |
| --- | --- |
| 累计量（`Volume/Turnover/OpenInt`） | `groupby(session_id).diff()`，会话首行 100% 为 NaN |
| 滚动特征（`rvol_20`、`trend_20`…） | `_rolling_stat(..., sid=...)` 会话内 groupby rolling |
| OFI 队列变化 | 会话首行置 NaN（上一会话的队列与本会话无关） |
| 未来标签 | `shift(-h)` 后，凡 `session_id[t] != session_id[t+h]` 一律 NaN |
| z-score / 波动标准化 | 会话内 `_zscore`，不跨会话拉均值 |

### 坑 3：部分合约的衍生列恒为零

多档撤单/笔数列（`DerSV*`/`DerBV*`/`SN*`/`BN*`）在部分合约（如 `au2608`）**整列恒零**，
并非 NaN，因此「喂进去再 dropna」是无效的。处理方式：

- `HFDataSource.available_fields(contract)` **逐列探测**（先 dropna 再判空，
  否则 `np.nanmin` 遇全 NaN 会炸或直接误判）；
- 因子层不硬依赖这些列 —— 恒零列对应的因子自然退化成常数，不参与模型。

## 3. 数据源：`HFDataSource`

`src/data/hf_adapter.py`，与 `OfflineDataSource` 完全同构，**adapter 不自读 `config.yaml`**，
由调用方把已解析的 dict 传进来。

```yaml
# config.yaml
data:
  source: hf                        # 与 legacy / neodata / offline 平级，走同一个 DataSourceFactory
  hf:
    file: "C:/Users/HP/Desktop/20251208.pqt"
    cache_dir: "data/hf/cache"      # 按合约切片缓存，带 mtime/size 校验
    orders_file: "C:/Users/HP/Desktop/附件3：20251208_orders.xlsx"
    search_dirs: ["data/hf", "C:/Users/HP/Desktop"]
    glob: "*2025*.pqt"
```

```python
hf = HFDataSource(config=cfg)
hf.inventory()                                  # 品种 / 合约 / 快照数 / 会话覆盖 / tick size
df  = hf.load_l2("au2602", sessions=("M", "E")) # 单合约快照序列
all = hf.load_symbol_l2("au")                   # 全月份 {contract: df}
k   = hf.get_minute_kline("au2602", freq="30min")
term = hf.get_term_structure("au")              # 期限结构（reindex nearest, tolerance=1s）
orders = HFDataSource.load_orders(orders_file)  # 自身委托流水
```

要点：

- **谓词下推**：15.8M 行不可整份读进内存，全部走 `pq.read_table(filters=...)`
  （不是 `ParquetFile.read(filters=)`，后者不支持）；合约名做了小写与全称映射后下推，
  能下推就绝不全表扫。
- **日 K 契约对齐**：`get_daily_kline(symbols, start, end, period, adjust)` 输出与
  `OfflineDataSource` 完全一致（`date/symbol/open/high/low/close/volume/amount/pct_chg`，
  `pct_chg` 为百分数、`date` 为字符串），因此 `data.source: hf` 可以像 `offline` 一样即插即用。
  `DayHigh/DayLow` 是当日**累计**极值，必须取末值（取首值会得到「开盘那一刻的极值」）。
- **`get_index_constituents`** 是股票语义的等价物：传品种代码返回该品种全部合约，
  传 `hf` 返回按快照数排序的最活跃前 N 个（快照数作为活跃度代理）。
- **`overlap_diagnostics`**：委托 vs 行情的秒级交集体检。**结论：日盘 M/E 高度对齐
  （au2602 99.9%、au2604 91.4%），夜盘零交集（au2608 委托落在 12-07、行情在 12-05）。**
  所以 —— **成交概率建模只能用日盘**；夜盘行情只能用于纯因子研究。

## 4. 高频因子层：`src/mining/hf.py`

### 4.1 因子清单（约 50 个，按信息类型分组）

| 组 | 代表因子 | 含义 |
| --- | --- | --- |
| 失衡 | `obi_l1`、`obi_w2/w3/w5` | 单档 / 多档**量加权**买卖失衡 |
| 价格 | `microprice`、`micro_dev_ticks`、`spread_ticks`、`mid` | 按最优档量加权的微观价格、偏离中价几个 tick、价差几个 tick |
| 形状 | `depth_ratio`、`best_share_*`、`book_slope`、`queue_decay`、`large_wall` | 盘口是厚还是薄、量堆在近档还是远档、有没有大单墙 |
| 动态 | `ofi`、`dq_b`、`dq_s`、`dq_b1..dq_b5` | 按价格匹配的队列净变化（OFI 的快照近似） |
| 短周期动能 | `rvol_20/100`、`trend_20`、`reversal_5`、`signed_flow_20` | 会话内滚动：已实现波动、动量、反转、主动方向净成交量 |

一切以 **tick 为单位**归一化（`micro_dev_ticks`、`spread_ticks`），否则不同品种不可比。
tick size 由 `estimate_tick_size` 从相邻价格差的 5% 分位估计，并**吸附**到国内期货常见报价单位：
价格为 float32 存储，直接差分会估出 `0.019958` 这类值，而黄金的真实报价单位是 `0.02`。

### 4.2 三条防泄漏纪律

1. **负向 `shift` 只允许出现在 `make_forward_labels`**（单元测试
   `test_labels_use_only_negative_shift_in_one_place` 会扫源码强制这件事）；
2. 未来标签按 **tick 数**而非秒定义 —— 秒不可靠（500ms 快照 + 会话空洞）；
3. **泄漏对照**：随机置换标签后 IC 必须塌到 ≈0。实测置换对照最大 `|IC| ≤ 0.0177`，
   而真信号 `|IC| = 0.1369`，信噪比约 **10×**。

### 4.3 因子有效性（au2602 日盘，时间序列 IC）

| 因子 | h=5 tick | h=10 tick | h=20 tick |
| --- | --- | --- | --- |
| `ofi` | **0.1369**（t=22.3） | 0.0999 | 0.0775 |

分位单调性：`ofi` 的 Spearman 单调度 **0.9447**，最低分组胜率 **39.8%** → 最高分组 **55.6%**。
这是典型的「信息随时间衰减」形态，也直接决定了下文的策略设计必须走得很快。

## 5. 监督模型层：`src/mining/hf_models.py`

### 5.1 方向模型（预测未来 mid 涨跌）

| 特征集 | train acc | **test acc** |
| --- | --- | --- |
| 全量 ~50 因子 GBDT | 0.5115 | **0.5339** |
| `CORE_HF_FACTORS`（10 因子） | 0.5443 | **0.5581** |

**结论（已固化为实现默认）**：全量因子反而更差 —— 在 5 万量级样本、信噪比 ~0.14 的场景下，
大量共线性弱特征只是在放大方差。核心 10 因子：
`ofi / dq_b / dq_s / dq_b1 / obi_w5 / obi_l1 / micro_dev_ticks / rvol_20 / spread_ticks / trend_20`。

重要性归因用 `permutation_importance`（`HistGradientBoostingClassifier` 没有 `feature_importances_`，
replace 这也是最容易写出假归因的地方）。

### 5.2 成交概率模型（做市的另一半：**先成交了才有资格谈逆向选择**）

特征全部严格撮合前：`price_aggr_ticks`（挂单价相对 mid 的激进度）、`queue_ahead`（排在自己前面的量）、
`size_vs_queue`、`obi_signed`、`micro_signed`、`spread_inv`。

委托与行情的拼接必须 `merge_asof(direction="backward")`：单向错，取到自己这笔**成交之后**的
盘口 = 自指泄漏。

| 指标 | 值 |
| --- | --- |
| AUC | **0.7948** |
| Top 十分位成交率 | **11.48%**（测试集基准 2.84%，**4.04× lift**） |
| 激进度分桶 | `-12.2 tick → 0.24%` … `+0.245 tick → 6.62%`（**27×** 单调） |
| Logistic 系数 | `price_aggr +`、`size_vs_queue −1.35`、`queue_ahead −` |

符号全部符合直觉：挂得越激进越容易成交；单子越大、前面排的队越长越难成交。

## 6. 四类高频策略层：`src/mining/hf_strategies.py`

统一评估器 `evaluate_signal(signal, forward_ret, cost_ticks, hold_ticks)`，两个关键口径：

- **按 `hold_ticks` 降采样**：若每 tick 都「成交」一次，同一段 10 tick 的价格变动会被
  重复计入 10 次，收益率凭空放大一个数量级；
- **仅在持仓方向变化时扣费**：`chg = (s.diff().fillna(s) != 0)`，持仓延续不重复付手续费。

跑法：`python scripts/hf_strategy_demo.py`（`--family trend|event|calendar|mm`）。

### A. 短周期趋势（OFI z-score）

| 组合（au2608 日盘） | 扣费前 净 tick/笔 | 扣 1 tick 后 | 胜率(扣费后) |
| --- | --- | --- | --- |
| h=10, entry=1.5 | +0.0556 | **−0.7650** | 43.9% |
| h=10, entry=2.0 | +0.5133 | **−0.4006** | 44.4% |
| h=20, entry=1.5 | +0.3092 | **−0.5521** | 45.7% |

**判据明确：裸 OFI z-score 在 ~1 tick 的双边换手成本下整体为负。**
ML 版本（`|p−0.5| > 0.20` 的高把握样本，au2608 h=10）毛利 **+1.55 tick/笔**，
扣 1 tick 后仍有 **+0.70 tick/笔**（59 笔，胜率 50.9%）—— 这是唯一一个在这个成本口径下
还活着的方向性交易，代价是样本骤减到 59 笔。

跨合约迁移同时被证否：`au2602 → au2608` 直接打分，扣费后 **−0.1485 tick/笔**。
**必须逐合约训练，不能指望月份间迁移。**

### B. 事件驱动（au2602 日盘，事件后 10 tick 的中价漂移）

| 事件 | 次数 | 事件后漂移 | 全样本基准 |
| --- | --- | --- | --- |
| `vol_burst`（波动突变） | 324（1.246%） | **+0.7654 tick** | +0.0086 |
| `spread_blowup`（价差撑大） | 82（0.315%） | −0.1951 tick | +0.0086 |
| `oi_shock`（持仓量突变） | 294（1.131%） | +0.1207 tick | +0.0086 |
| `oi_shock` 带方向 | 294 | −0.1990 tick | +0.0086 |

`vol_burst` 是唯一方向性明确、且幅度（0.77 tick）显著异于基准的事件；但仍小于单次换手成本，
**适合做「开仓触发器 / 过滤器」，不适合单独成策略**。

### C. 跨市场套利 —— 实际可做的是「同品种跨期」

数据只有一个交易所的快照，没有跨交易所/跨资产可用数据，因此验证的是**期限结构上的相对错误定价**：

| 价差 | 扣费前 | 扣 1 tick 后 | 胜率(扣费后) |
| --- | --- | --- | --- |
| au2512–au2601 | −0.0009 | **−0.4839** | 22.3% |
| au2512–au2612 | +0.0029 | **−0.5273** | 16.6% |
| au2601–au2612 | +0.0032 | **−0.6443** | 15.3% |

**扣费前就已经约等于 0**：这份单日样本里，简单的价差 z-score 均值回归没有可交易的预测力。
否定的是这个信号与这个样本，不是跨期套利本身。

### D. 被动做市 —— 逆向选择定价

`estimate_adverse_selection`：成交后用 `direction="forward"` 取成交后的价格，
用 `direction="backward"` 取下单前的 mid，`adverse = −side × move_ticks`
（**正值 = 成交后价格朝对自己不利的方向走**）。委托先按主动性分类 —— 被动单（被人点）与
主动单（自己去点）的逆向选择完全不是一回事。

| 合约 | 类型 | 笔数 | h=10 逆向选择 | 不利占比 |
| --- | --- | --- | --- | --- |
| au2602 | passive | 178 | −0.2388 tick | 41.0% |
| au2602 | aggressive | 92 | **−3.19 tick** | 16.3% |
| au2604 | passive | 62 | −0.2096 tick | 41.9% |
| ag2602 | passive | 29 | −1.1379 tick | 44.8% |
| ag2602 | aggressive | 59 | **−3.00 tick** | 23.7% |

解读（两侧同一枚硬币）：

- **自己的委托没有被显著逆向选择**（passive 平均为负 = 略微有利）；
- 但**主动跨价成交后 10 tick 平均同向漂移 3+ tick** —— 换到被动那一侧读，就是
  **被打的一方平均承受 ≈3 tick 的不利漂移**。

因此在这个样本里，被动报价的**半价差必须 ≥ 3 tick + 手续费**才谈得上安全，
1 tick 宽的报价会被系统性吃穿。这条数字直接来自 `market_making_edge = P(fill) × (half_spread − adverse)`
的参数敏感性。

## 7. 与统一因子挖掘框架的接驳

高频字段不是旁路玩具，而是被注册进了同一套 `FieldRegistry` / `PanelData` / 表达式树：

```python
from mining.hf import install_hf_features, register_hf_fields
from mining.panel import PanelData, default_registry

register_hf_fields(reg)                      # role = ROLE_ALT（撮合前的另类信息）
install_hf_features(panel, long_df, fields=[...], tolerance="600s")
ex.validate(ex.parse("mul(rank_cs(obi_w5), rank_cs(ts_pct(close, 1)))"), reg)   # 过
ex.validate(ex.parse("sub(ofi, close)"), reg)                                    # 拦：手数 − 价格
```

三点设计：

1. **`role = ROLE_ALT`**：订单簿是撮合前的信息，日频量价是撮合后的结果，二者属于不同信息源，
   在融合时不该被当成一个维度的重复暴露；
2. **`dimension`（量纲）进静态类型检查**：`obi_w5` 是无量纲比值、`ofi` 是手数、`bp1` 是价格，
   表达式树在**校验阶段**就能拦住「手数 − 价格」这类错；
3. **前向填充带耐受窗口**：高频是状态量，bar 之间缺失应沿用最近一次观测；但超过 `tolerance`
   （默认 600s，远大于 500ms 间隔，足以判定会话断裂/停盘）必须置 NaN，否则午休的旧快照
   会被一路填到下午开盘。**掩蔽要逐列求「最后一次真实观测时刻」** —— 用并集索引当观测时刻
   会退化成「永远不陈旧」（bar 时刻本身一定在并集里）。

跑法：`python scripts/hf_mining_demo.py --freq 30min --symbol au`。

### 7.1 一个必须说清楚的反面结果

| bar 频率 | `obi_w5` RankIC | `micro_dev_ticks` | `ts_pct(close,1)` |
| --- | --- | --- | --- |
| 30min | −0.0344 | −0.0512 | **−0.3183** |
| 5min | +0.0167 | +0.0074 | **−0.3434** |
| 1min | +0.0320 | +0.0353 | **−0.2443** |

**把订单簿因子聚合到分钟级 bar 上做横截面挖掘，IC 只有 0.01~0.05，比同一份数据上的价格动量
（−0.24~−0.34）小一个数量级。** 对比第 4.3 节 tick 级别 OFI 的 0.1369：信息的**半衰期远短于 1 分钟**，
一旦用 bar 平均把它抹平，就什么都不剩了。

这解释了本模块的形态学：高频因子**不在日频/分钟频挖掘里和价格动量正面竞争**，
它的正确位置是 tick 网格上的独立流水线（`hf_models` / `hf_strategies`），
以及作为 `ROLE_ALT` 的另类信息**补的角色**进入跨域融合。

## 9. 硬限制（读代码前请先读这一段）

1. **这是快照，不是逐笔。** OFI 只能是「双快照间按价格匹配的队列净变化」近似，
   不可与 Cont(2014) 的定义混写。
2. **只有一天。**
   所有数值都由这一天得出，不能外推。单日样本尤其不能用来支持任何「策略可用」的结论 ——
   第 6 节的判据（扣 1 tick 后的净收益）比「还原有没有 IC」更诚实。
3. **成交概率只能用日盘。** 夜盘委托与行情零交集（`overlap_diagnostics` 实测）。
4. **K 线 resample 会在休市期造假 bar。** 用 searchsorted 归桶 + 只保留有快照支撑的 bar
   （30min 栅格下 134 → 24 根），否则 K 线里混满零成交的伪样本。
5. **模型不跨月份迁移。** `au2602 → au2608` 直接打分，扣费后为负。
6. **不要脱离成本谈信号。** 本模块所有策略结论的判据都是 `cost_ticks=1.0` 下的净收益，
   而不是准确率或 AUC。

## 11. 对话式挖掘怎么吃高频

Agent（`src/agent/graph.py`）新增高频分支，两种开法：

```yaml
data:
  source: hf                 # 开法一：直接读 L2 现场构建面板
  # 或
  source: offline
  offline:
    hf:
      agent_mode: true       # 开法二：读离线压实产物（推荐，快）
      max_contracts: 24
      freq: "1min"
  hf:
    user_table: ""           # 开法三：你自己接进来的分钟/高频表
```

**开法三（用户接入自有数据源）**：只要有「时间 + 标的 + 价格」三列，csv / parquet /
xlsx 都认，列名中英文都能匹配（`date`/`datetime`/`成交时间`、`symbol`/`code`/`合约`、
`close`/`收盘价`…），认不出来的数值列自动挂 `hf_` 前缀进面板。合约码**不补零**。

### 高频是增强，不是替换

高频三条路都取不到数据时（`user_table` 没配、L2 快照不在、离线产物没 build），
Agent **回退到常规日频工作流**继续跑（离线/akshare/neodata/ths 照常取数），
只在日志里写明回退原因（`FactorAgent.hf_fallback_reason`），绝不把整个取数打死。
反过来也一样：用户接了数据源却没开高频，常规链路本来就该照常工作——这两条路径
互不依赖。

另有两处与日频不同的处理：

- **样本外切分按自然日**。分钟面板若按分钟数切，同一天的前后两半会分别进训练/测试，
  等于"看着答案考试"，指标虚高；现在按 `date` 的自然日切，只有一个交易日时干脆
  不报 OOS（诚实优于假指标）。
- **中性化跳过**（见上文第 2 条）与**命名名实相符**（第 3 条）保持不变。

走高频分支时和日频有三处硬性不同（都是踩过的坑）：

1. **不做 `zfill(6)`**。面板 `symbol` 是 `AU2601` 这种期货合约，补零会错位。
2. **跳过行业/市值中性化**。合约没有行业、没有市值，`get_industry_and_cap` 返回空，
   这里直接不调用，而不是让它「降级跳过」——降级会让因子自以为做了中性化。
3. **提示词必须改写契约**（`nodes._data_block()`）：明确 `date` 是分钟时间戳、横截面是
   同一分钟的所有合约、现金流量与状态量的口径不同，并**要求命名名实相符**——
   只有真用了 `hf_*` 列或分钟级信息才允许叫 HF/Intraday/Micro。
   这一条是 `HighFreqVolumeMomentum` 那次审查（日频 close/volume 却自称高频）的直接补丁。

## 12. 对话式挖掘的上传 + JEV 结构化

用户上传的图片/文本/PDF/表格走 `src/engine/upload_ingest.py`：

```
上传 → 落盘 data/uploads/ → 解析（图片=结构描述+可选 OCR，文本/PDF=正文，表格=DataFrame）
     → JEV 判定（类型/情绪/可对齐/前瞻风险/能否因子化/构造路径）
     → ① 判定摘要 + 摘录注入挖掘提示词
     → ② 表格若能对齐 date×symbol，直接派生外部因子列并入面板
```

JEV（`src/engine/jev.py`）不是聊天模型，一次调用并行问完六个判断题，返回类型化答案 +
校准概率，代码据此**硬分流**：

- `forward_looking ≥ 0.7` → 提示词里写明「含前瞻信息，禁止直接作为当期因子值」
  （研报常见「预计下半年回暖」，直接做因子即前视偏差）；
- `alignable < 0.4` → 说明无法并入 `date×symbol` 面板；
- `factor_hint = unusable` → 明确判定不可因子化，让 LLM 别硬凑。

**降级**：未配置 `TYPESAFE_API_KEY` 或调用失败时自动回退本地规则（`engine="heuristic"`），
永不阻塞挖掘流水线。**图片不造假 OCR**：没装 tesseract 就只给尺寸/主色等结构化描述。

配置见 `config.yaml` 的 `jev` 与 `data.uploads` 段；UI 在「Agent 对话」页的
「📎 上传材料」面板，上传后可见 JEV 判定表与派生出的外部因子名。

## 13. 图文识别模型：自己训一层，别只靠规则

判定"这份材料是什么"此前只有两条路：JEV（要 Key、要联网）和本地正则（快但糙）。
现在补上第三条：**在本机把小模型训出来，落盘，推理时优先用**。

```bash
python scripts/train_multimodal.py                        # 合成语料 + 合成图片
python scripts/train_multimodal.py --image-dir data/train_images   # 混入真实图片
```

产物（`config.yaml → multimodal.model_dir`，默认 `data/models/multimodal/`，已 gitignore）：

| 模型 | 学什么 | 产物 | 默认配置下实测（留出集） |
| --- | --- | --- | --- |
| 朴素贝叶斯 | 材料类型 / 情绪 / 是否含前瞻（三个头） | `nb_*.npz` | acc 0.838 / 0.962 / 0.952 |
| Transformer | 材料类型（语序、长程搭配） | `transformer_text.pt` | acc 0.838，macro-F1 0.840 |
| CNN | 图片版式：K 线 / 表格 / 文本页 / 其他 | `cnn_image.pt` | acc 0.984 |
| GNN（2 层 GCN） | 材料关系图上的类型传播 | `gcn_material.pt` | acc 0.490 |

### 为什么每个模型都不是凑数

- **朴素贝叶斯**是降级底线：词袋 + 加平滑闭式解，几十毫秒训完，**不依赖 torch**。
- **Transformer** 是唯一建模语序的（"预计……将"这类跨距离的前瞻线索）。
- **CNN** 让无字图片也能分类：判出 K 线图就直接覆盖类型判定为「行情截图」——
  图片没文字，正则必然判成"其他"，此时版式才是更硬的证据。
- **GNN** 吃的是关系：约 25% 的样本**既不写类型关键词也不写标的**（归档元数据里
  才有），纯文本模型在它们身上只能瞎猜；实测这类硬样本上 GNN acc **0.33** vs
  朴素贝叶斯 **0.21**（随机基线 0.14）——这就是图带来增量的证据，报告里单列
  `hard_node_check`，跑完自己看。

### 三条踩过的坑（都写进代码注释了）

1. **关系图必须稀疏。** 同标的上百份材料连成团 → 两层 GCN 过平滑，准确率直接掉到
   0.21（≈随机）。现在按权重做 kNN 剪枝，平均度 5.3。
2. **同质性要真的存在。** 最初合成数据里"类型"与"标的"独立，图上没有任何标签信息，
   GNN 学到死也是随机——已让标的与类型相关（期货合约多是行情/流水，个股多是公告研报）。
3. **训练任务不能太干净。** 模板零词汇重叠时朴素贝叶斯随手 100%，指标好看但证明不了
   任何事；现在掺入共用套话 + 随机亮度/噪声的图片，指标才是可解释的。

### 判定链与降级

```
JEV（需 TYPESAFE_API_KEY，联网）  →  本地模型（离线，毫秒级）  →  本地正则（兜底）
```

任一环节不可用就往下走，**永不阻塞挖掘**；`engine` 字段如实标注判定来源
（`jev` / `local-model` / `heuristic`）。torch 未安装时只训朴素贝叶斯，
`training_report.json` 里写明跳过原因。
