# 知识库接入与监控说明

已将两份资料接入 FactorGPT 的 Agent 知识库，使其可「自适应学习 / 调用」。

## 已接入内容

### 1. 因子字典（含代码）`因子字典_含代码.xlsx`
- 接入方式：复用 `scripts/import_factors.py` 导入 `data/learned_factors.jsonl`。
- 结果：606 个因子（含 `因子名` / `代码`（真实 Python 因子代码）/ `作者` / `研报` / `IC, IR, Sharpe, Fitness, Returns, DrawDown` 等指标）。
- Agent 能力：通过 `retrieve_template` 检索因子并**直接复用/调用其中的 Python 代码**；因子定义与指标也会进入对话上下文。

### 2. 因子日历 2024 `因子日历2024 (量化投资与机器学习).pdf`
- 该 PDF 为纯图片型（无内嵌文字），已用 EasyOCR（中文+英文）逐页 OCR。
- 接入方式（双通道，保证在线/离线都可检索）：
  - 在线语义检索：OCR 文本分块后写入 Chroma 向量库 `factor_knowledge`（集合）。
  - 离线兜底检索：分块落地到 `data/knowledge/因子日历2024/chunks.jsonl`，`FactorRetriever` 会自动加载进本地 jieba 语料。
- 这些条目**不含代码**，因此只作为「知识上下文」被检索，不会污染可调用因子模板。

## 检索机制（已改造 `src/rag/retriever.py`）
- `FactorRetriever` 统一检索语料 = `SEED_FACTORS` + `learned.all()` + `data/knowledge/**/chunks*.jsonl`。
- `retrieve_template(query)`：仅返回含 `code` 的因子（来自已学习因子库，即可调用）。
- `retrieve(query)` / 向量检索：返回知识上下文（含 PDF OCR 内容）。

## 监控进度
后台 OCR 进程把日志写入 `scripts/_ocr_pdf.log`：
```
python -c "print(open('scripts/_ocr_pdf.log',encoding='utf-8',errors='replace').read()[-2000:])"
```
或直接查看该文件。每 10 页打印一次进度（约 9 秒/页，全本 379 页约 55 分钟）。

## 续跑 / 重跑（断点续跑，已处理页数会自动跳过）
```
cd e:\factor-gpt
python scripts/ingest_knowledge.py --skip-xlsx --pdf "e:\factor-gpt\data\knowledge\factor_calendar_2024.pdf"
```
（PDF 已复制为 ASCII 文件名 `data/knowledge/factor_calendar_2024.pdf` 以避免中文/空格路径在后台启动时解析失败。）

## 完成后清理（可选）
- 删除临时复制的 PDF：`data/knowledge/factor_calendar_2024.pdf`
- 删除临时日志：`scripts/_ocr_pdf.log`、`scripts/_ocr_pdf.err`、`scripts/_ocr_status.txt`

# 二、腾讯 ima 研报知识库接入与订阅监控

在上述离线资料之外，接入了腾讯 ima 开放 API，实现「持续更新的券商研报库」与 FactorGPT 知识库联动。

## 凭证

在 `.env` 中配置（`.env` 已被 `.gitignore` 忽略，不会入库）：

```
IMA_CLIENT_ID=...
IMA_API_KEY=...
```

在 `ima.qq.com/agent-interface` 生成，**有效期仅一个月**，到期需重新生成并更新 `.env`，否则脚本会提示缺凭证。

## 三个脚本的分工

| 脚本 | 作用 | 单次成本 |
|------|------|----------|
| `scripts/ima_sync.py` | 把**自有**知识库的文档拉取、分块，写入 `data/knowledge/**/chunks.jsonl` 与 Chroma，供 Agent 检索 | 取决于库大小 |
| `scripts/ima_keyword_watch.py` | **轻量监听（推荐日常使用）**：按关键词定向检索订阅库，只报出基线之外的新研报 | 约 14~28 次请求 |
| `scripts/ima_subscription_track.py` | **全量目录快照**：递归遍历订阅库目录树，与上次 manifest 做 diff | 350+ 次分页请求，支持断点续爬 |

## 为什么日常用轻量模式

订阅库「智汇研」券商投行研报精选有 17,837 篇。全量枚举需 350+ 次分页请求（`get_knowledge_list` 单页上限 50），实测必然触发账户级频控 `220021`，需要跨多次运行断点续爬才能建立基线。而 `search_knowledge` 未被频控，一个关键词约 1 次请求，十几个词几秒跑完，且命中的正是你关心的主题。

选词要用**精确研究主题词**而非宽泛品类词。实测对比：

| 关键词 | 单页命中 | 判断 |
|--------|----------|------|
| 行业轮动 | 20 | 好，正是要盯的增量 |
| 量化择时 | 13 | 好 |
| 选股因子 | 7 | 好 |
| 期权 | 100+ | 太宽泛，噪音淹没信号 |
| ETF | 100+ | 太宽泛 |
| 指数增强 / 组合优化 / 另类数据 | 0 | 语料中无此表述，无效词 |

当前词表（14 个，2026-08-06 定稿，基线 66 篇）：多因子、选股因子、因子择时、量化择时、风格轮动、高频因子、基本面量化、行业轮动、机器学习、可转债量化、量化选股、红利低波、小市值、因子拥挤度。

## 常用命令

```bash
# 首次：只建立基线，不把存量全报成「新增」
python scripts/ima_keyword_watch.py --init --no-push

# 日常：只报真正的新增，并自动 commit & push
python scripts/ima_keyword_watch.py

# 只看某几个词（不改配置）
python scripts/ima_keyword_watch.py --keywords 多因子,行业轮动 --no-push

# 往词表追加一个词
python scripts/ima_keyword_watch.py --add-keyword 因子拥挤度

# 全量目录快照（可随时中断，下次自动续爬）
python scripts/ima_subscription_track.py --no-push
```

## 产物（`ima_subscription/`）

| 文件 | 说明 | 是否入库 |
|------|------|----------|
| `watch_keywords.json` | 监听词表，可自由增删 | 入库 |
| `keyword_seen.json` | 已知命中基线（media_id → 标题/来源/首次发现时间） | 入库 |
| `keyword_hits.csv` | 全部命中的扁平清单，Excel 可直接打开 | 入库 |
| `keyword_watch.md` | 追加式「新增研报」日报，每节即一次实际增量 | 入库 |
| `crawl_state.json` | 全量爬取的断点进度，机器相关 | 已 gitignore |

## 定时任务

已配置两个自动任务，无需手动运行：

- **ima订阅库变更跟踪**：每天 04:00，跑 `ima_subscription_track.py`，频控中断则保存断点、次日续爬。
- **ima研报关键词监听**：每天 08:00，跑 `ima_keyword_watch.py`，有新增时生成日报并推送 GitHub。

## API 能力边界（实测）

- `search_knowledge`：订阅/共享库**可用**，是轻量监听的基础。
- `get_knowledge_list`：可用但单页上限 50，高频调用触发 `220021` 账户级频控。
- `get_media_info`：对订阅/共享库返回 `220030`，**无法导出原文**。

因此订阅库的研报**不能**通过 API 自动灌进 FactorGPT 知识库，需要你在 ima 客户端手动复制到自有库，再由 `ima_sync.py` 摄入。自动化的价值在于：把「在 1.7 万篇里翻找」变成「对着一份几条到几十条的变更清单勾选复制」。
